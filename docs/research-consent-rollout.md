실사용자 회고 대화를 모델 평가·라벨링에 쓰기 위한 동의 정비 계획. 2026-09-27 작성.

관련: [`model-comparison-plan.md`](model-comparison-plan.md) §7.1 · `momentory-fe/docs/PLAY-DATA-SAFETY.md`

> ⚠ 이 문서는 법률 자문이 아니다. 현행 문서와 계획을 대조해 **무엇이 어긋나는지**와 **무엇을
> 고쳐야 하는지**를 정리한 것이다. 공개 전에 법률 검토를 받는 것을 권한다.

## 1. 설계 결정

### 1-1. 선택 동의(옵트인)로 간다

옵트아웃(기본 동의)이 아니라 **명시적 옵트인**으로 둔다.

- 회고 원문은 민감한 개인 기록이고, 라벨링은 **사람이 전부 정독**하는 작업이다. 자동 처리나
  로깅보다 노출 범위가 훨씬 넓어 "안 껐으니 동의한 것"으로 볼 자리가 아니다.
- 동의 여부가 **서비스 이용에 영향을 주지 않아야** 한다(거부해도 전 기능 사용 가능).
- 앱 설정에서 **언제든 철회**할 수 있어야 한다.

### 1-2. 동의는 버전을 기록한다 (boolean 아님)

`user_profiles` 에 `research_consent boolean` 하나를 두는 것으로는 부족하다. **어느 버전의
방침에 동의했는지**와 **언제 동의했는지**를 알아야 한다 — 방침이 또 바뀌면 재동의가 필요하고,
동의 시점이 이용 가능 범위를 가른다.

```
research_consents
  user_id         FK, NOT NULL
  policy_version  VARCHAR  NOT NULL   -- 예: "2026-10-01"
  agreed          BOOLEAN  NOT NULL   -- 거부도 기록한다(다시 묻지 않기 위해)
  agreed_at       TIMESTAMP NOT NULL
  revoked_at      TIMESTAMP NULL
  UNIQUE (user_id, policy_version)
```

거부를 기록하는 이유: 기록하지 않으면 "아직 안 물어본 사람"과 구분이 안 돼 매번 다시 묻게 된다.

### 1-3. **기존 기록을 동의 범위에 명시적으로 포함한다**

이게 일정을 가른다. 동의 문안이 "앞으로 작성하는 기록"만 덮으면 동의 시점 이후 데이터가
100건 쌓일 때까지 기다려야 한다. **"동의 이전에 작성한 기록을 포함한다"고 문안에 명시**하고
동의를 받으면, 동의한 사용자의 **기존 대화를 바로 쓸 수 있다.**

문안에 이 점을 흐리지 않고 분명히 적는 것이 조건이다. 흐리게 적고 기존 기록을 쓰는 것이
가장 나쁜 선택이다.

### 1-4. 철회하면 원문과 라벨을 지운다

"이미 비식별화해서 복원 불가하므로 유지한다"는 쪽이 운영은 편하지만, 데이터셋이 100건 규모라
**지우는 편이 약속하기도 지키기도 쉽다.** 철회 시:

1. 이후 이용을 중단한다.
2. `eval/data/` 의 해당 세션 대화와 골드 라벨을 지운다 — `--id-map` 이 가명↔원본 매핑을
   들고 있으므로 찾을 수 있다. **이것이 `--id-map` 을 버리면 안 되는 이유다.**
3. 이미 집계에 들어간 지표는 되돌리지 않되, 다음 집계부터 제외한다.

## 2. 개정 문안 (초안)

### 2-1. 처리방침 머리말

```
현행)  시행 예정일: 모멘토리 정식 출시일
       현재 모멘토리는 출시 준비 중입니다. 외부 서비스의 최종 계약 조건과 실제 구현
       사항에 따라 정식 출시 전 본 방침을 최종 확정합니다.

개정)  시행일: 2026년 O월 O일
       이전 버전: 2026년 O월 O일 ~ 2026년 O월 O일 (보관 링크)
```

### 2-2. 처리방침 §1 표 — `AI 회고·일기` 행

```
현행)  이용 목적: 회고 대화, 일기 생성과 보관, 서비스 안전성 확보

개정)  이용 목적: 회고 대화, 일기 생성과 보관, 서비스 안전성 확보,
       (별도로 동의한 이용자에 한해) 비식별 처리 후 AI 응답 품질의 평가·개선
```

### 2-3. 처리방침 §3 — 학습 이용 문장

```
현행)  모멘토리 팀은 AI 회고 내용을 자체 AI 모델의 학습 데이터로 사용하지 않습니다.

개정)  모멘토리 팀은 AI 회고 내용을 이용자가 별도로 동의한 경우에 한해, 개인을 알아볼 수
       없도록 비식별 처리한 뒤 AI 응답 품질의 평가·개선과 자체 모델 개발에 이용합니다.
       동의하지 않은 이용자의 회고 내용은 이 목적으로 이용하지 않으며, 동의 여부는
       서비스 이용에 영향을 주지 않습니다.
```

### 2-4. 처리방침 — 새 조항 (§4로 넣고 이후 번호를 민다)

```
4. AI 품질 개선을 위한 데이터 이용 (선택 동의)

모멘토리 팀은 AI가 감정을 더 정확하게 읽도록 개선하기 위해, 별도로 동의한 이용자의 회고
대화와 일기를 아래 범위에서 이용합니다. 이 동의는 선택이며, 동의하지 않아도 모든 기능을
그대로 이용할 수 있습니다.

· 이용 대상   회고 대화 내용과 그로부터 생성된 일기. 동의 시점 이전에 작성한 기록을
              포함합니다.
· 이용 목적   AI가 추정한 감정·강도가 실제와 맞는지 사람이 검토하고, 모델의 성능을
              측정·비교하며, 자체 모델을 개발하는 데 이용합니다.
· 비식별 조치 이용 전 이메일, 전화번호, 주민등록번호, 계좌·카드번호, 외부 서비스 계정,
              대화에 등장하는 사람 이름을 가리고, 이용자 및 대화를 식별할 수 있는 값을
              임의의 값으로 대체합니다.
· 열람 범위   모멘토리 팀의 지정된 담당자만 열람합니다. 제3자에게 제공하거나 위탁하지
              않습니다.
· 보유 기간   동의 철회 시 또는 회원탈퇴 시까지. 목적 달성 후에는 지체 없이 파기합니다.
· 동의 철회   앱의 [마이 > 설정]에서 언제든지 철회할 수 있습니다. 철회하면 이후 이용을
              중단하고, 해당 이용자의 대화와 그에 대한 검토 결과를 삭제합니다.
```

### 2-5. 약관 §6 — 마지막에 한 항 추가

```
이용자는 설정에서 별도로 동의한 경우, 모멘토리 팀이 비식별 처리를 거쳐 이용자의 대화와
일기를 AI 품질의 평가·개선 목적으로 이용하는 것에 동의할 수 있습니다. 이 동의는 선택이며
언제든지 철회할 수 있고, 동의 여부는 서비스 이용에 영향을 주지 않습니다. 기록에 대한
권리는 이용자에게 있습니다.
```

## 4. 일정과 순서

1. 문안 확정 + 법률 검토 → 시행일 결정
2. 시행일 **최소 7일 전** 사전 안내 (처리방침 §10)
3. 랜딩 문서 교체 + 앱 동의 화면 배포
4. 동의 수집 — **동의자 수가 목표 세션 수를 채울 때까지 기다린다**
5. 덤프 → 비식별화 → 라벨링 (계획 §7.1)

> ⚠ **2~3단계 동안 라벨링을 시작하지 않는다.** 동의 없이 만든 골드는 나중에 버려야 하고,
> 라벨링은 100건 기준 수 시간~수십 시간짜리 작업이다.

## 5. 그동안 막히지 않으려면

동의 수집을 기다리는 사이 **계획 §7.2의 자체 생성 세트로 라벨링 기준을 먼저 다듬는다.**
화자 3명이 확보돼 있고, 100건 파일럿의 목적이 "기준과 데이터의 가능성 확인"(정본 §9)이므로
기준 정비는 자체 생성 대화로 대부분 달성된다. 실사용 데이터는 동의가 모이는 대로 합류시킨다.

10~20건으로 기준을 잡고 `eval/merge.py` 로 첫 IAA를 보는 사이클(계획 §7.1)은 **지금 바로**
돌릴 수 있다.
