# 대화 전략 실험 집계 쿼리

Notion 「대화 전략 선택을 통한 효율적인 감정 탐색 기술」 5장의 지표를 DB 기록에서 뽑는다. 읽기만 하고, 테이블에는 아무것도 쓰지 않는다
(같은 연결 안에서만 사는 임시 뷰를 만든다).

## 실행

1. `00_setup.sql` 맨 위 `sm_params` 를 고친다.
   - `since`: 재려는 서버에 V48(세션 연구 로그, #115)이 배포된 시각. 그 전에 시작한 회고에는 종료 사유 · 탐색 질문 기록이 없다.
   - `until`: 수집 마감 시각. 마감 뒤 최종 분석에서는 꼭 고정한다.
   - `min_confidence`: 반응을 셀 확신 기준(문서 2장, 지금 0.5).
2. 같은 연결에서 `00_setup.sql` → 필요한 파일 순서로 실행한다.

```bash
psql "$DB_URL" -f 00_setup.sql -f 30_metrics.sql
```

IntelliJ 라면 같은 콘솔에서 `00_setup.sql` 을 먼저 실행한 뒤 다른 파일을 실행한다.

## 언제 무엇을 쓰나

| 시점 | 파일 | 보는 것 | 이상하면 |
|---|---|---|---|
| **수집 전** — dev 에서 테스트 대화 몇 건 한 뒤 | `10_check_logging.sql` | 기록 누락 0인지(종료 사유 · 탐색 질문 · 집단), 반응 분류가 고르게 나오는지 | 데이터를 모으기 전에 코드를 고친다 |
| **수집 중** — 주 1회 정도 | `10_check_logging.sql` | 누락이 새로 생기지 않았는지, 규칙 버전이 섞이지 않았는지 | 섞인 기간을 분석에서 뺄지 정한다 |
| **수집 중** — 주 1회 정도 | `20_progress.sql` | 집단별 표본(목표 집단당 약 120~190 세션), 처치 확인(첫 질문 선택형 · 질문 수 · 재해석), 시작 성향 분포 | 실험군이 다르게 동작하지 않으면 결과를 보기 전에 원인을 찾는다 |
| **성향 반영을 켜기 전** — 반영 끈 파일럿이 쌓인 뒤 | `40_premise.sql` | 사용자별 저항과 응답 곤란이 함께 움직이는지(가설 전제) | 관련이 없으면 가설 · 주 지표를 실험 전에 다시 정한다 |
| **수집 후** — `until` 을 고정하고 | `30_metrics.sql` | 집단별 응답 곤란률 · 저항률(세션 · 질문 있는 세션 · 질문 단위), 미완료 이탈률, 통계용 세션 표 | — |

결과를 본 뒤에 지표 정의(이 파일들)를 바꾸지 않는다. 바꿔야 하면 바꾼 이유와 날짜를 남긴다.

## 정의 요약

- **대상 세션**: 전략 대화 턴 기록(`policy_version`)이 있는 회고. 지표는 두 집단(`TREATMENT` · `CONTROL`) 가운데
  과거 성향 반영 조건을 충족한(`derived_*` 가 참) 세션만 본다.
- **탐색 질문**: `question_sent = true`. 선택형 포함. 공통 첫 질문 · 다른 기억 · 마무리 제안은 제외.
- **그 반응**: 같은 회고 다음 일기 턴의 Jev `reaction`. 응답 곤란 = `struggle_to_answer`,
  저항 = `refuse_question` · `no_answer_or_topic_change` · `argue`. 확신 0.5 미만은 세지 않는다.
- **미완료 이탈**: 시작한 하루(KST 04:00 경계)가 끝날 때까지 정상 정리(마무리 수락 · 다른 기억 없음 · 턴 상한)나
  사용자 요청으로 끝나지 않은 세션. 다음 날 이어서 끝냈어도 이탈이다. 안전 중단 · 악용 중단 · 같은 날 다른 경로 일기 ·
  아직 하루가 안 끝난 세션은 분모에서 빼고 따로 센다.

## 여기서 하지 않는 것

- **사람 판정**: 문서상 응답 곤란 · 저항의 주 판정과 감정 명료화는 집단을 모르는 평가자가 한다. 이 쿼리의 응답 곤란 · 저항은
  Jev 자동 집계라 사람 판정과 대조한 뒤 보조로만 쓴다. 감정 명료화율은 여기에 없다.
- **신뢰구간 · 사용자 묶음 분석**: `30_metrics.sql` 3번 표를 CSV 로 내보내 통계 스크립트로 한다.
- **알려진 빈틈**
  - 새 이야기로 넘어간 턴도 Jev 가 `no_answer_or_topic_change` 로 판단하면 저항으로 센다. 전략은 이런 턴의 저항을 되돌리지만,
    새 이야기였는지는 턴 기록에 남지 않는다.
  - 요청이 실패해 되돌려진 턴은 기록이 없다(일기 턴 번호가 빈다 — `10_check_logging.sql` 이 센다).
  - 시스템 오류가 낀 이탈은 자동으로 빼지 않고 `10_check_logging.sql` 4번에서 따로 보여 준다.
